VibeCheck — Architecture & Code Tour Guide

Plain-language guide to how VibeCheck extracts coding-agent claims, checks real GitHub repository files and commit diffs, and enforces server-side quote verification. Snapshot anchored at commit a7fac7b (static offline HTML, zero external dependencies).

1. Plain-Language Overview

VibeCheck catches false “done / fixed / tested” claims from AI coding agents before a solo builder discovers the gap at 2am. It consists of four main pieces:

  • The Inspector Page (src/app/page.tsx): Collects the agent message (or a GitHub PR/commit URL) and target repository URL, checks sessionStorage cache first, and runs the 3-step verification pipeline.
  • The GitHub Evidence Engine (src/app/api/check-evidence/route.ts & src/lib/github.ts): Fetches the repo file tree, scores up to 60 source files by keyword hits, and inspects recent commit diffs/patches.
  • The Spec-Drift & Quote Verifier (src/app/api/check-spec-drift/route.ts & src/lib/gemini.ts): Compares claims against devpost/scope.md, prd.md, and spec.md plus matched repo files, then verifies every cited quote verbatim in server code.
  • The Verdict & Report Surface (src/components/ResultsPanel.tsx & ReportExport.tsx): Renders the Build Honesty Scorecard, deep-linked GitHub citations, and exports self-contained Base64URL permalinks or PR Markdown tables.
✓ TRUE: Verbatim supporting line verified in repo file ⚠ SPEC-DRIFT: Verbatim contradiction in scope/prd/spec ? UNVERIFIED: No verified supporting line or restatement rejected

3. Three-Stop Reference Code Route (Tracing One Check)

Stop 1 — Entry & Orchestration: src/app/page.tsx → handleCheck()

When you click Check Claims, handleCheck(forceLive) hashes the input message/PR URL and repository URL via cacheKey(). On a cache miss, it chains three sequential POST requests using fetchWithTimeout(): /api/extract-claims → /api/check-evidence → /api/check-spec-drift, storing the result in sessionStorage only after all three succeed.

Stop 2 — Content-Based Evidence Retrieval: src/app/api/check-evidence/route.ts → POST()

Resolves the repository’s default branch via getDefaultBranch(), fetches the recursive Git tree and recent commits, and runs selectContentCandidates() + fetchRawFileTexts() in src/lib/github.ts. Each file is scored by how many distinct claim keywords appear in its content plus a path-match bonus, returning the top 5 files per claim along with matched commit diffs.

Stop 3 — Server-Side Quote & Keyword Guards: src/lib/gemini.ts → validateAssessments()

Even after Gemini proposes a supporting or contradicting quote, VibeCheck never trusts the model’s word alone. validateAssessments() runs three deterministic code checks: 

1. hasContradictionKeywords(claim.text, contradictingLine)  // Requires ≥2 shared non-stopword keywords for SPEC-DRIFT
2. findLineNumber(doc.text, quote)                         // Verifies the quoted line exists verbatim in the fetched file
3. isRestatement(claim.text, supportingQuote, lineText)    // Rejects lines that merely repeat the claim text

4. “To Change This, Start Here”

Change the 3 Self-Audit Claims

Edit src/lib/self-audit-claims.json, then run npm run regenerate-seed and npm run check-seed so the homepage seed stays in sync.

Adjust Retrieval File Caps or Excluded Folders

Open src/lib/github.ts and inspect CONTENT_EXCLUDED_DIRS, MAX_CONTENT_CANDIDATES (60), and MAX_FILES_PER_CLAIM (5).

Tune Verdict Guards or Model Fallback

Open src/lib/gemini.ts and inspect PRIMARY_MODEL, FALLBACK_MODEL, isRestatement(), and hasContradictionKeywords().

Add or Edit Scenario Presets

Open src/lib/demo-data.ts and edit SCENARIO_PRESETS or RETROACTIVE_AUDIT_CASEBOOK.

5. A Practice to Reuse

Pair AI judgment with a deterministic post-condition in code (src/lib/gemini.ts > validateAssessments).

Early in the build (Fixes 3–9), a claim could be marked TRUE whenever file names matched its keywords and Gemini reported no spec contradiction — meaning absence of contradiction was treated as proof. In Fix 10 and Fix 16, we changed the contract: the model must return an exact line from a fetched file, and server code deterministically checks findLineNumber(), isRestatement(), and hasContradictionKeywords() before assigning a verdict. On any future AI project, let the model propose structured candidates, but enforce the acceptance rule in deterministic code tested by fast offline unit tests (npm run test).
