VibeCheck — Architecture & Code Tour Guide

Plain-language guide to how VibeCheck extracts coding-agent claims, checks real GitHub repository files and commit diffs, and enforces deterministic server-side guards. Snapshot anchored at commit 6746621 (static offline HTML, zero external dependencies).

1. Plain-Language Overview

VibeCheck catches false “done / fixed / tested” claims from AI coding agents before a solo builder discovers the gap at 2am. It consists of four main pieces:

  • The Inspector Page (src/app/page.tsx): Collects the agent message (or a GitHub PR/commit URL) and target repository URL, automatically activates demo mode on /?demo=1, checks sessionStorage cache first, and runs the 3-step verification pipeline.
  • The GitHub Evidence Engine (src/app/api/check-evidence/route.ts & src/lib/github.ts): Validates the GitHub URL via parseGitHubRepoUrl(), fetches the repo file tree, scores up to 60 source files by keyword hits + AST-lite declaration bonuses, and inspects matched commit diffs/patches.
  • The Spec-Drift & Quote Verifier (src/app/api/check-spec-drift/route.ts, src/lib/gemini.ts, & src/lib/verification-guards.mjs): Compares claims against devpost/scope.md, prd.md, and spec.md plus matched repo files, then verifies every cited quote via deterministic whole-line, comment-spoof, negation, and keyword guards.
  • The Verdict & Signed Report Surface (src/components/ResultsPanel.tsx, ReportExport.tsx, & src/lib/report-crypto.mjs): Renders the Build Honesty Scorecard, deep-linked GitHub citations, and exports HMAC-SHA256 signed Base64URL permalinks or PR Markdown tables.
✓ TRUE: Non-comment executable/config line verified in repo file ⚠ SPEC-DRIFT: Contradiction verified in scope/prd/spec ? UNVERIFIED: No verified supporting line or rejected by guards

3. Three-Stop Reference Code Route (Tracing One Check)

Stop 1 — Entry & Orchestration: src/app/page.tsx → handleCheck()

When you click Check Claims, handleCheck(forceLive) locks auditedRepoUrl, checks sessionStorage via cacheKey(), and chains three sequential POST requests using fetchWithTimeout(): /api/extract-claims → /api/check-evidence → /api/check-spec-drift.

Stop 2 — Content-Based Evidence Retrieval: src/app/api/check-evidence/route.ts → POST()

Validates the repository URL via parseGitHubRepoUrl(), resolves the default branch via getDefaultBranch(), excludes .agents/, .claude/, devpost/, and benchmark/ across all retrieval stages, and scores up to 60 source files by keyword hits plus AST-lite declaration bonuses.

Stop 3 — Server-Side Quote & Keyword Guards: src/lib/gemini.ts & src/lib/verification-guards.mjs

validateAssessments() runs five deterministic code checks before assigning a verdict: 

1. hasContradictionKeywords(claim.text, contradictingLine)  // Requires ≥2 shared non-stopword keywords for SPEC-DRIFT
2. findLineNumber(doc.text, quote)                         // Whole-line aware verbatim match in the fetched file
3. isExecutableCodeLine(lineText, supportingFile)          // Rejects code comments and TODO/FIXME placeholders
4. hasNegationMismatch(claim.text, lineText)               // Rejects positive claims paired with negated lines
5. isRestatement(claim.text, supportingQuote, lineText)    // Rejects lines that merely repeat the claim text

4. “To Change This, Start Here”

Change the 3 Self-Audit Claims

Edit src/lib/self-audit-claims.json, then run npm run regenerate-seed and npm run check-seed so the homepage seed stays in sync.

Adjust Retrieval File Caps or Excluded Folders

Open src/lib/github.ts and inspect CONTENT_EXCLUDED_DIRS, MAX_CONTENT_CANDIDATES (60), and MAX_FILES_PER_CLAIM (5).

Tune Verdict Guards or Model Fallback

Open src/lib/verification-guards.mjs and src/lib/gemini.ts to inspect isExecutableCodeLine(), hasNegationMismatch(), isRestatement(), and hasContradictionKeywords().

Add or Edit Scenario Presets

Open src/lib/demo-data.ts and edit SCENARIO_PRESETS.

5. A Practice to Reuse

Pair AI judgment with a deterministic post-condition in a shared, directly tested module (src/lib/verification-guards.mjs).

Let the model propose structured candidates, but enforce the acceptance rule in deterministic code (`findLineNumber`, `isExecutableCodeLine`, `hasNegationMismatch`, `isRestatement`, `hasContradictionKeywords`) imported directly by both the production route and `npm run test` (`scripts/test-core.mjs`).
